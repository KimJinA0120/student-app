# 수강생 관리 사이트 설계

작성일: 2026-10-27 · 수정: 2026-10-28 (요구사항 정리 반영) · 요구사항 문서의 기술 상세

## 기술 스택

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| 백엔드 | Spring Boot (실행 가능한 jar 하나) | jar 안에 웹서버 포함, 서버 PC엔 Java만 설치 |
| 화면 | Thymeleaf 서버 렌더링 | 7~10명 내부용, 프론트 분리 불필요 |
| DB | H2 파일 모드 + JPA | 설치 없음, Spring Boot 기본 지원, 웹 콘솔 제공, 파일 하나로 백업 |
| 컨테이너 | 사용 안 함 | 1달·소규모라 이점 없음, 윈도우 서버 PC에서 관리 부담만 늘어남 |

## 아키텍처

```
[매니저 노트북들] --(내부망, 브라우저)--> [서버 PC: 내부망IP:3000]
                                          ├─ app.jar (Spring Boot)
                                          └─ data/appdb.mv.db (H2)
```

컨트롤러 → 서비스 → 리포지토리(JPA) → H2의 단순 구조. 로그인 없음, 작성자 기록 없음.

## 서버 PC 폴더 구조

```
C:\student-app\
 ├─ app.jar
 ├─ application.properties   ← 외부 설정 (jar 옆에 두면 우선 적용)
 ├─ start.bat                ← java -jar app.jar
 ├─ data\                    ← H2 DB 파일
 └─ backup\
```

서버 PC용 application.properties:

```properties
server.port=3000
spring.datasource.url=jdbc:h2:file:C:/student-app/data/appdb;AUTO_SERVER=TRUE
spring.datasource.username=sa
spring.datasource.password=(설정)
spring.jpa.hibernate.ddl-auto=update
spring.h2.console.enabled=true
spring.h2.console.path=/h2-console
```

- 반드시 `jdbc:h2:file:` 사용 (`mem:`은 재시작 시 데이터 소멸)
- 운영 시작 후 Spring Boot·H2 버전 변경 금지 (H2 파일 형식 호환 문제)
- `ddl-auto=create` 운영 금지
- 다른 노트북에서 H2 콘솔을 열려면 `spring.h2.console.settings.web-allow-others=true` (DB 비밀번호 필수)

## 배포·업데이트

개발은 다른 PC에서 하고 jar만 옮긴다.

1. 개발 PC: `./gradlew bootJar` (또는 `mvn package`)
2. 공유 폴더·USB로 jar를 서버 PC에 복사
3. 업데이트 시: 사용자 공지 → 앱 종료 → DB 백업 → app.jar 교체 → start.bat 실행 → 접속 확인

DB 파일은 jar 밖에 있으므로 jar 교체로 데이터가 바뀌지 않는다.

## 서버 PC 운영 체크

- 내부망 IP 고정
- 윈도우 방화벽 3000 포트 인바운드 허용
- start.bat 시작프로그램 등록, 절전 모드 해제
- 백업: 앱 종료 후 data 폴더 복사, 또는 H2 콘솔에서 `SCRIPT TO 'C:/student-app/backup/backup.sql'` (실행 중 파일 그대로 복사 금지)
- 서버 PC 시계가 맞아야 함 (현재 교시 자동 판정에 사용)

## DB 테이블

**공통 컬럼** (BaseEntity): `created_at`, `updated_at`

### 수강생

| 테이블 | 컬럼 |
| --- | --- |
| `student` | id, name(필수), phone, age, hope_class, attend_id, start_date, memo |
| `student_hope_instructor` | student_id, instructor_id — 희망 강사 (여러 명) |

### 수업

| 테이블 | 컬럼 |
| --- | --- |
| `lesson` | id, date, period(1~4), room_no(FK), instructor_id(FK), start_time(선택), end_time(선택), ended_at(선택) |
| `lesson_student` | lesson_id, student_id — 한 수업에 수강생 1명 이상 |

- 팀/개인 구분 컬럼 없음. 수강생 수 = `lesson_student` 행 수
- [추가] = 진행 중 수업에 `lesson_student` 행 추가
- [종료] = `ended_at` 기록, [취소] = `lesson` 삭제 (확인 후)

### 강사

| 테이블 | 컬럼 |
| --- | --- |
| `instructor` | id, name, phone |
| `instructor_slot` | id, instructor_id, day_of_week, period, role(주/보조), note |
| `instructor_override` | id, instructor_id, type(ABSENT/CONDITIONAL/EXTRA/NOTE), start_date, end_date, periods(비면 전 교시), memo |
| `instructor_day_status` | id, instructor_id, date, status(BREAK/OUT/LEAVE_EARLY), from_period, changed_at |

- 하루짜리 예외는 start_date = end_date
- 휴식·외출은 [복귀] 시 행 삭제. 조퇴는 `from_period` 이후 교시를 근무에서 제외
- 교시 체크박스(`periods`)는 문자열 한 칸(`1,3`)으로 저장하고 AttributeConverter로 Set 변환

### 운영 매니저

| 테이블 | 컬럼 |
| --- | --- |
| `manager` | id, name, phone |
| `manager_shift` | id, manager_id, day_of_week, start_time, end_time |
| `manager_exception` | id, manager_id, date, type(휴무/시간변경), start_time, end_time, memo |

### 공통

| 테이블 | 컬럼 |
| --- | --- |
| `room` | no, name, type(일반/상담실/창고 겸용), sort_order |
| `check_item` | id, content, person_name(선택), resolved, resolved_at |

`room` 초기 데이터: 일반 6개(sort 1~6), 상담실(sort 7), 창고 겸용(sort 8). 설정 화면 없음.

## 계산 규칙 (저장하지 않고 조회 시 계산)

규모가 수백 건이라 필터링은 Java에서 처리한다.

**기준 시점**
- 기본: 오늘 + 현재 시각 → 교시 판정. 12:00~13:00은 2교시, 18:00~19:00은 4교시, 21:30 이후는 4교시
- 사용자가 날짜·교시 또는 시각을 지정하면 그 값을 쓴다 (쿼리 파라미터)

**강사 근무 (날짜 d, 교시 p)**
- 확정 = d 요일의 instructor_slot(p) + EXTRA(d, p) − ABSENT(d, p) − 조퇴(d, from_period < p)
- 조건부 = CONDITIONAL(d, p), "조"로 별도 표시, 인원수 미포함
- NOTE와 결근 메모는 그날 아래에 표시

**진행 중 수업 (d, p)**
- lesson(d, p) 중 ended_at 없음, 그리고 (end_time이 있으면 기준 시각 < end_time, 없으면 기준 시각이 교시 종료 전)
- 교시 종료 후에는 자동으로 종료로 본다 (별도 배치 작업 없음)

**근무 중 강사 패널 한 줄 상태**
- 진행 중 수업이 있으면 → 수업 중 (강의실, 학생 수)
- 아니면 instructor_day_status → 휴식 / 외출 / 조퇴
- 둘 다 없으면 → 표시 없음, [수업시작]

**강의실 자동 매칭**
- room 중 (d, p)의 진행 중 수업이 쓰지 않는 교실, sort_order 순 첫 번째

**희망 강사 알림**
- 수강생 1명 + 희망 강사 있음 → 희망 강사 ∩ 확정 근무 − 수업 중 강사
- 결과가 있으면 "OO 강사님이 수업하나요?", 없으면 "희망 강사 부재 / 수업 중" 안내

**방문 회차**
- 수강생별 lesson_student 행 수

**부족 표시 (강사 탭 표 머리, 전체 달력)**
- 교시별 확정 인원 ≥ 8 → 초록, 미만 → 주황 ("부족 n" = 8 − 확정 인원)

**매니저 (날짜 d)**
- 근무 = d 요일의 manager_shift − 휴무, 시간변경은 바뀐 시간으로 표시
