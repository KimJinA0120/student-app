# 수강생 관리 사이트 운영 가이드 (서버 PC)

서버 PC(윈도우) 한 대에서 사이트를 켜 두고, 매니저 노트북은 `서버 PC 내부망 IP:3000`으로 접속한다.
이 문서는 서버 PC 설치부터 백업·복구·업데이트까지의 절차를 정리한다. (기술 배경은 `수강생 관리 사이트 설계.md` 참고)

## 0. 한눈에 보기

```
C:\student-app\
 ├─ app.jar                  ← 사이트 프로그램 (개발 PC에서 빌드해서 복사)
 ├─ sheet.xlsx               ← 상담일지·업무일지 첫 이전용 엑셀 (이전이 끝나면 지움, 1-3-1)
 ├─ application.properties   ← 서버 PC용 설정 (DB 위치·비밀번호). jar 안의 설정보다 우선
 ├─ start.bat                ← 서버 켜기 (창을 닫으면 사이트가 꺼짐)
 ├─ backup.bat               ← DB 백업 (서버를 켠 채로 가능)
 ├─ restore.bat              ← 백업으로 되돌리기 (서버를 끈 뒤)
 ├─ firewall.bat             ← 방화벽 3000 포트 허용 (처음 한 번, 관리자 권한)
 ├─ register-backup-task.bat ← 매일 22:00 자동 백업 등록 (처음 한 번)
 ├─ data\appdb.mv.db         ← DB 파일 (처음 실행할 때 자동 생성)
 ├─ backup\                  ← 백업 zip
 └─ logs\app.log             ← 서버 로그
```

- 저장소의 `deploy/` 폴더에 bat 파일과 `application.properties`가 있다.
- `app.jar`는 개발 PC에서 `./gradlew bootJar`로 만든 `build/libs/app.jar`.

## 1. 처음 설치 (한 번만)

### 1-1. Java 21 설치

1. Eclipse Temurin **21 JRE** (Windows x64 `.msi`)를 내려받아 설치한다. 설치 화면에서 "Add to PATH"와 "Set JAVA_HOME"을 켠다.
2. 명령 프롬프트에서 확인: `java -version` → `21.x`가 나오면 된다.

### 1-2. 파일 복사

1. `C:\student-app` 폴더를 만든다. (다른 위치를 쓰면 bat 파일과 `application.properties`의 경로를 모두 바꿔야 한다)
2. `app.jar`와 `deploy/` 안의 파일을 모두 `C:\student-app`에 복사한다.
3. `application.properties`를 메모장으로 열어 `spring.datasource.password=` 뒤를 실제 비밀번호로 바꾼다.
   - **영문·숫자만** 쓴다 (`backup.bat`이 이 값을 읽는데, `& % ^ !` 같은 문자는 bat에서 깨진다).
   - 비밀번호는 DB를 **처음 만들 때** 정해진다. 나중에 바꾸려면 H2 콘솔에서 `ALTER USER SA SET PASSWORD '새비밀번호'` 후 설정 파일도 같이 바꾼다.
   - 이 비밀번호는 따로 적어 둔다 (H2 콘솔·백업 복구에 필요).

### 1-3. 처음 실행 + 기존 강사 일정 옮기기

기존 강사 일정 HTML(`안양_강사일정_요일별_전체.html`)을 `C:\student-app`에 복사한 뒤, 명령 프롬프트에서 **한 번만** 실행한다.

```
cd /d C:\student-app
java -Duser.timezone=Asia/Seoul -jar app.jar --app.legacy-import.file=안양_강사일정_요일별_전체.html
```

- 로그에 `기존 일정 이전 완료: 강사 31명, ...`이 나오면 성공. 강사 테이블이 이미 차 있으면 건너뛴다(두 번 실행해도 중복 안 됨).
- 이전한 내용을 원본과 날짜·교시별로 비교해서, 다르면 전부 취소하고 오류를 낸다.
- 교실 8개는 처음 실행할 때 자동으로 들어간다.
- 확인이 끝나면 창을 닫고(`Ctrl + C` 또는 창 닫기), **HTML 파일은 서버 PC에서 지운다** (강사 연락처가 들어 있는 개인정보).

### 1-3-1. 상담일지·업무일지 옮기기 (자동, 처음 한 번만)

업무 시트 엑셀(`안양상설교육장업무시트.xlsx`)의 **"상담" 시트**는 상담 탭으로, **"업무일지" 시트**는 업무일지 탭으로 옮긴다. 명령어는 필요 없다.

1. 엑셀 파일을 `C:\student-app`에 복사하고 이름을 **`sheet.xlsx`**로 바꾼다.
   - 위치·이름은 `application.properties`의 `app.sheet-import.file`에 적혀 있다.
2. `start.bat`으로 서버를 켠다. 로그에 `상담일지 이전 완료: 27건 (sheet.xlsx)`, `업무일지 이전 완료: 6건 (sheet.xlsx)`이 나오면 성공.
3. 사이트의 상담 탭·업무일지 탭에서 확인한 뒤, **엑셀 파일은 서버 PC에서 지운다** (상담자 연락처가 들어 있는 개인정보).

- 서버를 켤 때마다 확인하지만, **상담일지(업무일지)가 비어 있을 때만** 넣는다. 둘은 따로 판단한다. 한 번 들어가면 파일이 남아 있어도 다시 넣지 않는다.
  - 그래서 엑셀을 넣기 전에 그 탭에 직접 한 건이라도 적으면 이전이 일어나지 않는다. 직접 적은 것을 지우고 서버를 다시 켜면 된다.
- 상담 시트에서 읽는 칸: 성명 · 연락처 · 희망 수업 · 희망 요일 · 희망 시간 · 비고 · 상담일. "-"는 빈 칸으로, 이름·연락처가 모두 빈 줄은 건너뛴다.
- 업무일지 시트에서 읽는 칸: 날짜 · 1~4교시 · 강사 · 신규 · 기존 · 특이사항. 요일·계는 사이트가 계산한다. 날짜만 있고 내용이 없는 줄은 건너뛴다.
- 파일이 없으면 건너뛴다. 읽다가 오류가 나면 **한 건도 넣지 않고** 로그(`logs\app.log`)에 `상담일지 이전 실패`(또는 `업무일지 이전 실패`)를 남긴다. 서버는 그대로 켜진다.

### 1-4. 내부망 IP 고정

1. 명령 프롬프트에서 `ipconfig` → 사용 중인 어댑터의 `IPv4 주소` (예: `192.168.0.20`)를 확인한다.
2. IP가 바뀌면 노트북에서 접속 주소가 달라지므로 고정한다.
   - 공유기 관리 화면에서 서버 PC MAC 주소에 IP 예약(DHCP 고정 할당), 또는
   - 윈도우 설정 → 네트워크 → 어댑터 속성 → IPv4 → 수동 IP 지정 (센터 네트워크 담당자와 상의)

### 1-5. 방화벽 열기

`firewall.bat`을 마우스 오른쪽 → **관리자 권한으로 실행**. 같은 내부망(로컬 서브넷)에서만 3000 포트 접속을 허용한다.

### 1-6. 자동 시작 · 절전 해제

- **시작프로그램 등록:** `Win + R` → `shell:startup` 입력 → 열린 폴더에 `start.bat`의 바로 가기를 만든다 (원본은 `C:\student-app`에 그대로 둔다).
- **절전 해제:** 설정 → 시스템 → 전원 → "절전 모드" 를 **안 함**으로. (화면 끄기는 괜찮다)
- **윈도우 업데이트:** 설정 → Windows 업데이트 → 고급 옵션 → 사용 시간을 09:00~22:00으로 설정해 사용 중 자동 재시작을 막는다.
- **시계:** 현재 교시 자동 판정에 서버 PC 시계를 쓴다. 설정 → 시간 및 언어 → "자동으로 시간 설정"을 켜고 시간대가 `(UTC+09:00) 서울`인지 확인한다.

### 1-7. 자동 백업 등록

`register-backup-task.bat`을 실행하면 매일 22:00에 `backup.bat`이 자동 실행된다. (작업 스케줄러에 `student-app backup`으로 보임)

### 1-8. 접속 확인

1. 서버 PC: `start.bat` 실행 → 창에 `Tomcat started on port 3000`이 나오면 브라우저에서 `http://localhost:3000`.
2. 매니저 노트북: 같은 와이파이/내부망에서 `http://192.168.0.20:3000` (1-4에서 확인한 IP). 바탕화면에 바로 가기나 즐겨찾기를 만들어 둔다.

## 2. 매일 운영

- 서버 PC를 켜면 `start.bat` 창이 자동으로 뜬다. **이 창을 닫으면 사이트가 꺼진다** (최소화는 괜찮다).
- 끌 때: `start.bat` 창을 닫는다. 데이터는 저장할 때마다 바로 DB 파일에 기록되므로 따로 저장할 필요는 없다.
- 백업은 매일 22:00 자동. 서버 PC가 그 시각에 꺼져 있으면 그날은 건너뛰므로, 퇴근 전에 `backup.bat`을 직접 눌러도 된다.

## 3. 백업

- `backup.bat` 실행 → `backup\appdb-20261110-220000.zip` 생성. **서버를 켠 채로** 해도 된다 (H2의 `BACKUP TO` 명령 사용).
- 실행 중인 `data\appdb.mv.db`를 탐색기로 직접 복사하지 않는다 (복사 도중 기록이 일어나면 깨진 파일이 될 수 있음). 꼭 복사하려면 서버 창을 닫은 뒤에.
- 30일 지난 백업 zip은 자동으로 지워진다.
- 서버 PC 고장에 대비해 **주 1회 이상 `backup` 폴더의 최신 zip을 USB 등 다른 곳에 복사**한다 (개인정보가 들어 있으므로 보관에 주의).
- 실패하면 `backup\last-backup.log`에 이유가 남는다 (대부분 비밀번호 불일치).

## 4. 복구 (백업으로 되돌리기)

1. 매니저들에게 잠시 사용 중지를 알린다.
2. `start.bat` 창을 닫는다.
3. 명령 프롬프트에서:
   ```
   cd /d C:\student-app
   restore.bat backup\appdb-20261110-220000.zip
   ```
   (인자 없이 `restore.bat`만 실행하면 백업 목록이 최근순으로 나온다)
4. `Y` 입력 → 지금 DB는 `backup\before-restore-시각\`으로 옮겨지고 백업 내용으로 바뀐다.
5. `start.bat` 실행 → 화면에서 데이터 확인.

- 백업 시각 이후에 입력한 내용은 사라지므로, 그 사이 입력분은 다시 입력해야 한다.
- 서버 PC 자체가 고장 났으면: 새 PC에 1장 설치를 하되 1-3(강사 일정 이전)은 건너뛰고, `backup` 폴더를 만든 뒤 USB의 zip을 넣고 위 3~5를 진행한다. 비밀번호는 백업할 때의 비밀번호와 같아야 한다.

## 5. 업데이트 (새 app.jar로 교체)

**개발 PC**

1. 테스트 통과 확인 후 `./gradlew bootJar` → `build/libs/app.jar`
2. 공유 폴더나 USB로 서버 PC에 옮긴다.

**서버 PC** (사용자가 적은 시간에)

1. 매니저들에게 몇 분간 사용 중지를 알린다.
2. `backup.bat` 실행 (업데이트 직전 백업).
3. `start.bat` 창을 닫는다.
4. 기존 `app.jar`의 이름을 `app-old.jar`로 바꾸고, 새 `app.jar`를 복사한다.
5. `start.bat` 실행 → 각 탭을 열어 확인.
6. 문제가 있으면: 창 닫기 → `app.jar` 삭제 → `app-old.jar`를 `app.jar`로 되돌리기 → (데이터가 이상해졌으면 4장 복구) → `start.bat`.

- 새 `deploy/application.properties`에 설정이 추가됐으면, 서버 PC의 `application.properties`를 **덮어쓰지 말고**(비밀번호가 지워짐) 추가된 줄만 메모장으로 옮겨 적는다.
  - 예: 상담일지·업무일지 이전용 `app.sheet-import.file=C:/student-app/sheet.xlsx` (1-3-1 참고)
- DB 파일은 jar 밖(`data\`)에 있어서 jar를 바꿔도 데이터는 그대로다. 새 컬럼·테이블은 `ddl-auto=update`가 자동으로 추가한다.
- **운영 중에는 Spring Boot·H2 버전을 올리지 않는다** (`build.gradle`의 버전 고정). H2 버전이 바뀌면 기존 DB 파일을 못 읽을 수 있다.
- `application.properties`의 `ddl-auto`를 `create`로 바꾸지 않는다 (DB 전체가 지워진다).

## 6. H2 콘솔 (DB 직접 보기)

- 서버 PC에서 `http://localhost:3000/h2-console`
  - JDBC URL: `jdbc:h2:file:C:/student-app/data/appdb;AUTO_SERVER=TRUE`
  - 사용자: `sa`, 비밀번호: 1-2에서 정한 값
- 조회용으로만 쓰고, 직접 수정·삭제는 하지 않는다 (화면의 검증을 거치지 않음). 꼭 필요하면 먼저 백업한다.
- 다른 노트북에서 열어야 할 때만 `application.properties`의 `spring.h2.console.settings.web-allow-others=true`로 바꾸고 서버를 다시 켠다. 끝나면 다시 `false`로.

## 7. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| `start.bat` 창에 `Port 3000 was already in use` | 서버가 이미 켜져 있다 (작업 표시줄의 다른 창 확인). 다른 프로그램이 3000을 쓰면 `netstat -ano \| findstr :3000`으로 찾는다 |
| `'java'은(는) 내부 또는 외부 명령...이 아닙니다` | Java 설치·PATH (1-1) |
| 노트북에서 접속 안 됨 (서버 PC에서는 됨) | 서버 PC IP가 바뀌었는지(`ipconfig`), 방화벽(1-5), 같은 네트워크인지 |
| 수업 기록 폼의 기본 교시·[조퇴] 버튼 표시가 이상함 | 서버 PC 시계·시간대 (1-6) |
| 화면이 안 바뀌고 오래 걸림 | `logs\app.log` 맨 아래 오류 확인 → 창 닫고 `start.bat` 다시 실행 |
| `Database may be already in use` | 서버 창이 두 개 떠 있지 않은지 확인 |
| `Wrong user name or password` | `application.properties`의 비밀번호가 DB를 처음 만들 때와 같은지 |

## 8. 사용 기간이 끝난 뒤 (12/10 이후)

1. `backup.bat`으로 마지막 백업.
2. 필요한 기간만 보관할 곳(USB 등)에 zip을 옮기고, 보관 기간이 지나면 지운다 (수강생·강사 개인정보).
3. 시작프로그램 바로 가기, 작업 스케줄러 `student-app backup`, 방화벽 규칙 `student-app 3000`을 지운다.
4. `C:\student-app` 폴더를 지운다.
